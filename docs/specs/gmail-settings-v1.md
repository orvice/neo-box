# Google Workspace Gmail 设置 v1：只读概览与自动回复

## Problem Statement

用户已经能在 Neo Box 中管理多个 Workspace Tenant 的用户、群组和安全操作，但查看或处理某个人的 Gmail 设置仍要登录 Google 管理控制台，且管理控制台不显示用户自己配置的转发、委托和过滤器。管理员代离职员工设置自动回复、排查账号是否被设置了外部转发时，没有统一入口，也没有访问记录。

本 spec 的范围来自访谈：第一版只提供 Gmail **设置**（不读邮件），读取概览并支持自动回复写入；转发、委托、过滤器的写操作留到后续。访问他人设置必须模拟该用户，因此每次访问都要先记录并由用户说明原因。边界决策见 [ADR 0008](../adr/0008-gmail-settings-impersonation-with-logged-access.md)。

## Solution

在 Workspace User 详情中新增 **Gmail 设置** 页。进入前填写访问原因并重新输入目标邮箱，通过后读取该用户的自动回复、自动转发与转发地址、委托、过滤器摘要和发信身份。外部转发、转发到外部的过滤器、自动删除的过滤器被标出。管理员可以启用、修改和关闭自动回复。

所有访问（读和写）先写入 Workspace operation 再发送；记录只保存结构摘要，不保存邮件设置的文本内容。

## User Stories

1. 作为管理员，我希望在 Tenant 的授权说明中看到 Gmail 所需的两个 scope，以及它们不包含读取邮件，以便放心授权。
2. 作为管理员，我希望进入用户的 Gmail 设置前必须填写原因并输入目标邮箱，以便每次访问都有说明。
3. 作为管理员，我希望只能访问当前 Tenant 的用户，以便不会误访问其他组织。
4. 作为管理员，我希望看到用户的自动回复状态、起止日期、主题和正文，以便了解对外回复。
5. 作为管理员，我希望启用、修改和关闭自动回复，以便为离职或休假员工代设。
6. 作为管理员，我希望看到自动转发是否开启、转发到哪个地址、已登记的转发地址及其验证状态，以便发现邮件外流。
7. 作为管理员，我希望转发目标在 Tenant 域名之外时被明确标出，以便优先排查。
8. 作为管理员，我希望看到用户的委托列表及状态，以便知道谁能代为收发邮件。
9. 作为管理员，我希望看到过滤器列表及动作，并标出“转发”“自动删除”“跳过收件箱”，以便发现隐藏邮件的规则。
10. 作为管理员，我希望看到发信身份（send-as）及验证状态，以便发现伪装发件地址。
11. 作为管理员，我希望缺少 Gmail scope、用户没有邮箱或被停用时，只在该页看到明确原因，以便区分原因而不影响 Tenant 健康。
12. 作为管理员，我希望在操作记录中看到谁在何时因何原因访问了谁的 Gmail 设置，以便事后追查。
13. 作为管理员，我希望操作记录不含自动回复正文、过滤器条件或转发地址，以便记录本身不泄露内容。
14. 作为用户，我希望其他 Neo Box 用户无法访问我的 Connection、Tenant 和这些记录，以便保持隔离。

## Implementation Decisions

### 授权与模拟

- 新增两个可选 scope：`gmail.settings.basic`（自动回复、过滤器、IMAP/POP）和 `gmail.settings.sharing`（转发、委托、发信身份）。仅在 Gmail 设置请求中申请；基础用户操作、Tenant 授权检查及其他可选功能的 scope 不变。读取概览申请两者，只改自动回复时仅申请 basic。
- 每次请求先用 Tenant 管理员经 Directory 解析目标用户并校验 Customer ID，之后才以该用户的主邮箱为 subject 换取 token。别名、其他 customer 的用户、解析不到的地址不得换 token。token 单次请求使用，不缓存。
- 不申请任何邮件内容 scope，不申请 Drive scope。

### 确认与记录

- 请求必须带访问原因（1–200 字）和重新输入的目标邮箱，后端校验，缺失即拒绝。一次确认只针对一个 Tenant 内的一个用户，有固定的短有效期；有效期内同页面连续读写可复用，到期或切换用户需重新确认。
- 复用 `workspace_operations`：新增 action `gmail.settings.read`、`gmail.vacation.update`，并保存访问原因。读和写都先落 pending 记录，落库失败则不发送；写入只发送一次，读取按现有规则重试。
- 记录只含白名单摘要：自动回复是否启用及日期范围、过滤器数量、转发规则数量、是否存在 Tenant 域名之外的目标。不含正文、主题、过滤器条件、标签名、转发或委托地址、token、Google 原始错误信息。
- 操作记录页增加按读/写筛选。

### 读取内容与风险标记

- 自动回复、自动转发、转发地址、委托、过滤器、发信身份各自独立读取，某项失败只标记该项，不让整页失败；未取得的值显示为未知，不当作未开启。
- 风险标记仅基于已读取到的数据：转发目标不属于该 Tenant 的任何已验证域名；过滤器含转发动作、删除动作或跳过收件箱。不产生 Alert，不影响 Connection 或 Tenant 健康。
- 页面实时读取，不保存设置内容；提供手动刷新。

### 自动回复写入

- 支持启用、修改（主题、正文、起止时间、是否仅限联系人 / 域内）、关闭。修改以读取到的当前值为基础，保留表单未展示的字段。
- 写入后重新读取确认。远端未确认的结果显示为未知，不自动重发。

### API 与前端

- 新增 Workspace 专属 RPC（读取概览、读取/更新自动回复），遵循 buf lint 与现有 Connect 错误约定：缺少 Gmail scope 为 PermissionDenied，凭据被拒为 FailedPrecondition（不返回 Unauthenticated），写入未确认为 Unknown。
- Tenant 的 Gmail scope 缺失不改变 Tenant 的基础授权状态。
- 前端在用户详情增加 Gmail 设置标签与确认对话框，沿用 `front/src/api/google-workspace.ts` 的 hooks 和现有 UI 组件。外部目标判断等有逻辑的部分放在独立模块并附 Vitest 测试。

### 测试策略

- 主要边界为 Connect application 服务：沿用现有 Workspace 服务测试的模拟 Google API 与内存 Repository。
- 覆盖：缺少原因或目标邮箱被拒；其他 customer 的用户不换 token；别名不能作 subject；pending 记录写不进去则不发送；读与写的记录内容不含正文、条件和地址；单项读取失败不影响其他项；scope 缺失的错误映射；自动回复修改保留未展示字段；写入未确认为未知且不重试。
- 外部目标判断、过滤器动作归类用前端 Vitest。PostgreSQL 仓库测试验证新 action 与访问原因字段的存取和用户隔离，未配置 `NEOBOX_TEST_POSTGRES_DSN` 时如实报告跳过。
- 真实 Gmail 行为需要授权的测试租户，没有则明确写成未验证。

## Acceptance Criteria

- [ ] 没有访问原因或目标邮箱不一致时，后端拒绝任何 Gmail 设置请求。
- [ ] 其他 Tenant / customer 的用户、别名和未找到的地址无法触发 token 换取。
- [ ] 每次读取和写入在发送前有 pending 记录；记录失败时不发送。
- [ ] 操作记录含访问原因，但不含自动回复正文、过滤器条件、转发 / 委托地址、token 和 Google 原始错误。
- [ ] 概览展示自动回复、转发、委托、过滤器和发信身份；单项失败只影响该项，未知与关闭可区分。
- [ ] 外部转发和高风险过滤器被标出，且只依据已读取的数据。
- [ ] 可以启用、修改、关闭自动回复，保留未展示字段；未确认的写入显示未知且不重发。
- [ ] 缺少 Gmail scope 只在 Gmail 页显示，不改变 Tenant 健康。
- [ ] 请求只申请 Gmail 设置 scope，不含邮件内容或 Drive scope。
- [ ] 适用的后端、PostgreSQL 仓库、前端测试、构建和生成检查通过；跳过项明确报告。

## Out of Scope

- 读取、搜索、导出或修改邮件内容、标签、附件。
- 转发、委托、过滤器、发信身份的新增、修改和删除。
- 跨用户批量扫描（例如找出所有外部转发的用户）及自动告警。
- IMAP/POP 和语言设置的修改。
- Google Drive 相关功能。
- 向被访问的用户发送通知。

## Further Notes

- 本文档只是 spec，当前不启动实施。
- 实施前核对当时的 Gmail API 文档：各 settings 方法所需 scope、委托和转发地址仅限服务账号 + 域级委托调用的限制、转发地址的验证流程、`vacation` 的更新语义。
- 域级委托授权后，Service Account 能访问该 Tenant 的任何用户设置；Neo Box 的原因与目标确认是问责手段，不是授权。文档须向管理员说明。
- 后续顺序建议：转发 / 委托 / 过滤器写操作 → 有范围限制的外部转发扫描与告警 → Drive 治理。
